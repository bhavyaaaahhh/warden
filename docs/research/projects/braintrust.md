## Purpose
Braintrust is a hosted platform for both offline and online evaluation. Offline: `Eval()` runs a task over a dataset, scores each row and records an **experiment**. Online: the same span/logging API writes production **project logs**, and server-side "online scoring rules" score them **[doc]**. The open SDKs handle three things: instrumentation (span trees plus many provider/framework auto-patchers), the eval runner, and thin clients for datasets, experiments and summaries. autoevals is a separate, framework-agnostic scorer library: LLM-classifier judges defined as YAML templates, string, embedding and JSON scorers, and RAGAS ports. It targets product teams who want a code-first eval loop with a hosted UI for diffing and review.

## Core abstractions

### Unit of data: `EvalCase` (test case)
`PY framework.py:EvalCase` ([L91-L110](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L91-L110))
```python
input: Input
expected: Expected | None = None
metadata: Metadata | None = None
tags: Sequence[str] | None = None
trial_count: int | None = None        # per-row override
# only set when the case comes from a Dataset:
id, _xact_id, created, origin: ObjectReference, upsert_id
```
Trade-off: `input` is opaque JSON, with no conversation or turn structure. It is also the default **identity key** for comparing experiments **[doc]**, so a volatile field in `input` (timestamp, session id) breaks row alignment unless you set a custom comparison key in project settings (docs "compare-experiments", KB "Blank comparison rows due to mismatched inputs"). Per-row `trial_count` is a good small touch.

`data` accepts many shapes: iterable, iterator, awaitable, a zero-arg callable, a `Dataset`, or `BaseExperiment` ([`EvalData`, L296-L306](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L296-L306)). `BaseExperiment(name=None)` reuses a previous experiment's rows as the dataset. If `name` is None, it asks the server for the base experiment (`fetch_base_experiment` → `POST /api/base_experiment/get_id`) and iterates it via `as_dataset()` ([_run_evaluator_internal_impl L1879-L1897](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L1879-L1897); [ExperimentDatasetIterator L4276](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L4276) yields only root spans, meaning `root_span_id == span_id`).

### Batch execution: `Evaluator` / `Eval()` (experiment)
`PY framework.py:Evaluator` ([L319-L465](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L319-L465)), built by `Eval()` ([L947](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L947)) via `_EvalCommon` ([L677-L815](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L677-L815)).
Fields: `project_name, eval_name, data, task, scores, classifiers, experiment_name, metadata, tags, trial_count=1, is_public, update, timeout, max_concurrency, project_id, base_experiment_name, base_experiment_id, git_metadata_settings, repo_info, error_score_handler, description, summarize_scores, parameters`.
- `task`: `Callable[[Input], Output]` or `Callable[[Input, EvalHooks], Output]`, sync or async. The arity is sniffed with `get_signature(task)`, and a second parameter gets `hooks` (L1690-L1696). `EvalHooks` ([L159](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L159)) exposes mutable `metadata` and `tags`, `expected`, `span`, `trial_index`, `parameters` and `report_progress`.
- Experiment-level `metadata` and `tags` go to `init_experiment` and are stored on the experiment row. Row-level `metadata` is copied per row and can be mutated by the task through hooks.
- Registration side effect: when loaded by the `braintrust eval` CLI (`_lazy_load`), `Eval()` only registers into the global `_evals` and returns an empty summary (L748-L756).
- JS equivalent: `JS framework.ts:Evaluator` ([L227](https://github.com/braintrustdata/braintrust-sdk-javascript/blob/2634cce523a742bbeff3a8c42ebc138ba4791fa5/js/src/framework.ts#L227)), with `trialCount` (L286), `timeout` (L312), `signal: AbortSignal` (L317), `maxConcurrency` (L323), `errorScoreHandler` (L362) and `Eval` ([L742](https://github.com/braintrustdata/braintrust-sdk-javascript/blob/2634cce523a742bbeff3a8c42ebc138ba4791fa5/js/src/framework.ts#L742)).

Trade-off: the whole config is one flat dataclass. That is easy to start with, but experiment identity, runtime knobs and comparison policy all live in one object.

### Unit of scoring: scorer (function or `Scorer` class)
Python scorer contract ([`EvalScorer`, L263-L268](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L263-L268); `SyncScorerLike`/`AsyncScorerLike` L246-L260). A scorer is any callable taking keyword arguments drawn from `{input, output, expected, metadata, trace, id, tags}`. The runner **filters kwargs by the callee's signature** (`_call_user_fn_args`, [L497-L530](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L497-L530)). There is also a legacy fallback that assigns unmatched kwargs to leftover parameters **positionally** even when the names differ (L516-L523, flagged for removal).

Return shape (`OneOrMoreScores`, [L239-L241](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L239-L241)): `float | int | bool | None | Score | ScoreDict | NamedScoreDict | Sequence[Score|NamedScoreDict]`. The runner normalizes this to `list[Score]` ([await_or_run_scorer L1510-L1557](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L1510-L1557)). A bare number becomes `Score(name=<scorer name>)`. A list lets one scorer emit several named scores.

`PY score.py:Score` ([L24-L54](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/score.py#L24-L54)):
```python
name: str
score: float | None = None   # None == "skipped"
metadata: Metadata = {}
error: Exception | None      # deprecated; errors now propagate
def __post_init__(self):
    if self.score is not None and (self.score < 0 or self.score > 1): raise ValueError(...)
```
- Scores are **hard-bounded to [0,1]** at construction. Everything is a normalized float. There is no native pass/fail, integer or unbounded metric type.
- `Scorer` ABC ([L140](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/score.py#L140)) has `eval`, `eval_async` and `_run_eval_sync`. autoevals scorers subclass it.
- Separate concept: **classifiers** (`Classification{id, name, label, metadata}`, [L94](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/score.py#L94)) are recorded under `classifications`, not `scores`, and power UI group-by **[doc]**. This splits categorical from numeric outputs cleanly.
- JS: `EvalScorer = (args: EvalScorerArgs) => OneOrMoreScores | Promise<...>` with `EvalScorerArgs = EvalCase & { output; trace?: Trace }` ([L172-L191](https://github.com/braintrustdata/braintrust-sdk-javascript/blob/2634cce523a742bbeff3a8c42ebc138ba4791fa5/js/src/framework.ts#L172-L191)). JS uses a single object argument instead of signature sniffing.

### Execution record: span / trace (shared online + offline)
`PY logger.py:Span` ([L274](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L274)), `SpanImpl` ([L4724](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L4724)). Each span is **one logical row** keyed by `id`. Repeated `span.log(**event)` calls are *merged* into it (`log_internal`, [L4880-L4900](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L4880-L4900), which writes `id, span_id, root_span_id, span_parents` plus an `IS_MERGE_FIELD`). Event fields are the same for experiments and logs: `input, output, expected, error, scores, metadata, metrics, tags, span_attributes{type,name,purpose}` ([Experiment.log L4401-L4430](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L4401-L4430)).
- Tree: `span_parents: list[str]` (a list, so a DAG is possible) plus `root_span_id` for the trace id ([SpanIds / resolution L4060-L4125](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L4060-L4125)).
- Span types: `llm, score, function, eval, task, tool, automation, facet, preprocessor, classifier, review, question, log` ([span_types.py](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/span_types.py)).
- The parent is a container object (`experiment`, `project_logs`, `playground_logs`). The **same span API** writes to an `Experiment` (offline) or a `Logger` from `init_logger` (online, [L1900](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L1900)). Only the parent object differs. That is why online scorers and offline scorers can share code **[doc: score-online]**.
- Eval span layout per row/trial: root `eval` span (input, expected, output, merged metadata) → child `task` span → sibling `score`/`classifier` spans with `span_attributes.purpose="scorer"` ([L1640-L1700, L1516-L1524](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L1640-L1700)). Scores are logged on each scorer span and aggregated per root **[inferred]**.
- Scorers can read the trace. `scorer_kwargs["trace"]` is a `LocalTrace` ([L1767](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L1767); [trace.py:LocalTrace L490](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/trace.py#L490)) with `get_spans(span_type=, filters=, include_scorers=False)` and `get_thread(preprocessor=)`. `get_spans` first reads an **in-process span cache** (a disk-backed cache that is only enabled during evals, [_run_evaluator_internal L1474-L1497](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L1474-L1497); experiment spans are written to it in `log_internal` L4916-L4933), then falls back to a BTQL fetch after a single shared flush (`_ensure_spans_ready`, [L622](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/trace.py#L622)). `get_thread()` calls a **server-side "preprocessor" function** (`invoke(global_function="project_default"|"thread", function_type="preprocessor")`, [L598-L620](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/trace.py#L598-L620)) that turns the span tree into a message list **[server logic: doc/inferred]**.

Trade-off: a single merged-row model for every span type is simple, and it lets offline and online share one schema and UI. The cost is that turn, tool-call and LLM-call semantics are conventions on `span_attributes.type` and `metadata` keys, not typed records. See how `getToolName` probes `span_attributes.name`, `name`, `metadata.tool_name`, `metadata["gen_ai.tool.name"]` and `mcp.server` ([JS agent-assertions.ts L492-L516](https://github.com/braintrustdata/braintrust-sdk-javascript/blob/2634cce523a742bbeff3a8c42ebc138ba4791fa5/js/src/agent-assertions.ts#L492-L516)).

### Dataset
`PY logger.py:Dataset` ([L5252](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L5252)), `init_dataset(project, name, version=, environment=, dataset_id=, ...)` ([L1793](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L1793)).

Reads can be pinned (`version=` → `pinned_version`, [ObjectFetcher L3377-L3400](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L3377-L3400)). An **environment** tag (e.g. "production") resolves to a version via `GET environment-object/dataset/<id>/<env>` ([L5320-L5326](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L5320-L5326)). An explicit `version` beats `environment`.
- Experiment ↔ dataset linkage: `init()` sends `dataset_id` and `dataset_version` ([L1741-L1750](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L1741-L1750)). Each eval row gets `origin = {object_type:"dataset", object_id, id, _xact_id, created}` ([L1627-L1645](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L1627-L1645)), so every result can be traced to the exact row version it came from.
- The legacy `use_output` mode renames `expected`→`output` (deprecated, L5269-L5273).

Trade-off: MVCC-style versioning with no explicit snapshot objects is cheap and makes every write implicitly versioned. But "version" is just the max xact id, so there are no named or immutable releases apart from environment pointers **[inferred]**.

### Comparison: base experiment + summary
- **How the SDK picks the base** (`PY logger.py:init`, [L1725-L1739](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L1725-L1739)):
  1. `base_experiment_id`, if given, is sent as `base_exp_id`.
  2. Otherwise `base_experiment` (a name) is looked up with `GET experiment?experiment_name=` and the first hit's id is used. A miss only logs a warning.
  3. Otherwise, **if git metadata collection is enabled** (it defaults to the org setting, else `collect="none"`, L1712-L1719), the SDK sends `ancestor_commits = get_past_n_ancestors()`: up to 1000 `git rev-list --first-parent` commits starting at `merge-base(HEAD or HEAD^ if clean, origin/<default-branch>)` ([gitutil.py L109-L140](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/gitutil.py#L109-L140)). The **server** picks the experiment on the closest ancestor commit **[doc: `init` docstring L1630 "closest ancestor on the default (e.g. main) branch"]**.
  4. With no base and no git info, the server falls back to the most recent experiment in the project **[doc: `summarize` docstring L4558; compare-experiments docs say "most recent experiment on the same git branch" when git metadata exists]**. UI-level "Set baseline" and a project default baseline override this in the UI **[doc]**.
- **Summary**: after the run, `run_evaluator` calls `experiment.summarize(comparison_experiment_id = evaluator.base_experiment_id or experiment.data["base_exp_id"])` ([L1435-L1461](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L1435-L1461)). That hits `GET /experiment/<id>/summarize` ([L4551-L4611](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L4551-L4611)) and returns per score `ScoreSummary{score (avg), diff, improvements, regressions}` and per metric `MetricSummary` ([L6292-L6365](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L6292-L6365)). **All diffing is server-side [doc/inferred].** Rows are matched across experiments by comparison key (default `input`, configurable as a SQL expression such as `[input.query, metadata.category]`). `improvements` and `regressions` are counts of matched rows whose score went up or down **[doc: compare-experiments]**. No significance test or confidence interval appears in any SDK type or doc **[inferred]**.
- Offline fallback (`no_send_logs`): `build_local_summary` computes an unweighted mean per score, ignoring `None`, with `diff=None, improvements=0, regressions=0` ([L1952-L1984](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L1952-L1984)). So **local runs cannot compare**.

## Execution model
- **Python**: everything is asyncio. The runner iterates `data` (converting sync iterables to async generators) and **creates one `asyncio.Task` per (row, trial) up front** (`tasks.append(asyncio.create_task(with_max_concurrency(...)))`, [L1926-L1940](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L1926-L1940)). `max_concurrency` is an `asyncio.Semaphore` around each row task. The default is `None`, meaning unbounded ([L1914-L1924](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L1914-L1924)). Sync user functions run in a shared `ThreadPoolExecutor(cpu_count())` with contextvars copied in (`await_or_run`, [L478-L494](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L478-L494); `EvalThreadPoolSingleton` L1268). All scorers and classifiers for a row run concurrently with `asyncio.create_task` (L1784-L1791). Results are awaited in order.
- **Trials**: `trial_count = datum.trial_count ?? evaluator.trial_count`, a plain loop that yields independent rows (L1933-L1939). Each trial is its own root span. With `upsert_id`, trial > 0 gets a deterministic `uuid5("braintrust:eval:<upsert_id>:trial:<i>")` so re-runs overwrite rather than duplicate (L1653-L1658; JS L1332-L1338). Nothing downstream consumes trials as a group: no per-case variance, pass@k or agreement statistic in the SDK. autoevals issue [#219](https://github.com/braintrustdata/autoevals/issues/219) raises exactly this.
- **Timeout**: Python applies `asyncio.wait_for(..., evaluator.timeout)` to the **whole evaluator** ([L1445](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L1445)). There is no per-row or per-scorer timeout. JS races the queue against a timeout/AbortSignal promise and marks `cancelled` so tasks that have not started are skipped ([L1657-L1713](https://github.com/braintrustdata/braintrust-sdk-javascript/blob/2634cce523a742bbeff3a8c42ebc138ba4791fa5/js/src/framework.ts#L1657-L1713)).
- **JS concurrency**: an async `queue(worker, maxConcurrency ?? MAX_SAFE_INTEGER)` ([L1301, L1628](https://github.com/braintrustdata/braintrust-sdk-javascript/blob/2634cce523a742bbeff3a8c42ebc138ba4791fa5/js/src/framework.ts#L1301)). Under `maxConcurrency`, the worker flushes the background logger when pending bytes cross a threshold, for backpressure ([L1618-L1624](https://github.com/braintrustdata/braintrust-sdk-javascript/blob/2634cce523a742bbeff3a8c42ebc138ba4791fa5/js/src/framework.ts#L1618-L1624)).
- **Error handling** (Python [L1795-L1852](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L1795-L1852)):
  - Task exception: caught per row, `root_span.log(error=...)`, `EvalResult.error/exc_info` set, and no scores are computed for that row.
  - Scorer exception: the other scorers still count. Failing scorer names map to tracebacks in `metadata["scorer_errors"]`, which is re-logged on the root. The run continues.
  - `error_score_handler(root_span, datum, unhandled_scores)` lets you fill in scores for missing scorers. `default_error_score_handler` logs **0** for each ([L1464-L1471](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L1464-L1471)). Without it, missing scores are simply absent, so they are excluded from the mean **[inferred from build_local_summary; server likely the same]**.
  - A subtle issue: `unhandled_scores` is a `nonlocal` shared across all row tasks (L1599, L1819-L1826), so concurrent rows race on it **[code smell; verified by reading, not by test]**.
- **Retries**: the SDK itself does not retry tasks or scorers. Log upload retries `NUM_RETRIES` (default 2) and then **drops the batch** with a printed warning ([_HTTPBackgroundLogger L1085, L1379-L1426](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L1379-L1426)). autoevals retries LLM calls **only on `RateLimitError`**, up to 100 times with ×1.5 backoff from 0.1s ([oai.py:run_cached_request L620-L646](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/py/autoevals/oai.py#L620-L646)). Other errors propagate.
- **Caching**: no task or judge result cache. `run_cached_request` is not a cache despite the name. `EmbeddingSimilarity` has an unbounded, process-global `_CACHE` dict keyed by text (string.py L112-L165).
- **Long-running / async workflows**: `workflow_eval.py` (experimental) handles agents whose task is "submit, then poll or webhook later". It persists pending per-case state in a `WorkflowEvalStore` (memory or Redis) and resumes scoring on completion ([workflow_eval.py L76-L506](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/workflow_eval.py#L76)). This is an unusual and useful design for slow agent runs.

## Data model & storage
- Persisted objects **[doc/inferred from API calls]**: project → experiments (with `repo_info`, `base_exp_id`, `dataset_id/version`, `parameters_id/version`, `metadata`, `tags`, [init L1698-L1768](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L1698-L1768)), datasets, project_logs, prompts and functions. Every row, in experiments and logs alike, is the same merged span record with `_xact_id`. Queries go through BTQL/SQL (`/btql`).
- Versioning: datasets by `_xact_id` plus environments; parameters and prompts by version id; experiments are immutable-by-name unless `update=True` (`ensure_new = update is not True`, L1700).
- Git provenance: `repo_info` (commit, branch, dirty, author, and so on) is gathered per `GitMetadataSettings` and drives base selection.

## Judge implementation (autoevals)
- **Template format**: YAML with `prompt` (Mustache) and `choice_scores` (label → float), plus optional `model`, `use_cot`, `temperature` and `max_tokens` (`ModelGradedSpec`, [AE js/templates.ts L14-L21](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/js/templates.ts#L14-L21); Python `ModelGradedSpec` llm.py L296). Shipped templates: `battle, closed_q_a, factuality, humor, possible, security, sql, summary, translation` ([AE templates/](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/templates/)). Example, [factuality.yaml](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/templates/factuality.yaml): options A–E map to `{A:0.4, B:0.6, C:1, D:0, E:1}` (subset/superset/same/disagree/immaterial-diff), derived from OpenAI Evals' fact template.
- **Class chain**: `OpenAILLMClassifier` ([L169](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/py/autoevals/llm.py#L169)) → `LLMClassifier(name, prompt_template, choice_scores, model=None, use_cot=True, ...)` ([L306-L412](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/py/autoevals/llm.py#L306)) → `SpecFileClassifier`. `SpecFileClassifier` maps the class name CamelCase→snake_case to find `templates/<name>.yaml` ([L499-L538](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/py/autoevals/llm.py#L499-L538)). `Battle`, `ClosedQA`, `Factuality` and the rest are empty subclasses ([L543, L611, L664](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/py/autoevals/llm.py#L543)). Adding a judge means adding a YAML file and a one-line class.
- **Choice scoring + CoT**: the prompt is `template + "\n" + (COT_SUFFIX if use_cot else NO_COT_SUFFIX)` ([L76-L88](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/py/autoevals/llm.py#L76-L88)). Output is forced through **function calling**: a single tool `select_choice` whose `choice` parameter is a JSON-schema `enum` of the choice labels, plus a required `reasons` string when CoT is on ([build_classification_tools L115-L133](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/py/autoevals/llm.py#L115-L133); `tool_choice` forced, L227-L233). Parsing takes the first tool call, checks the name, `json.loads(arguments)`, strips `choice` and reads `choice_scores[choice]`. The rationale goes to `metadata.rationale` ([_process_response L262-L278](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/py/autoevals/llm.py#L262-L278)). `use_cot` defaults to **True**.
- **Failure handling**: no tool call, a wrong tool name or empty choices raise `ValueError`. An out-of-enum choice (which the enum should prevent) would raise `KeyError`. There is no retry on parse failure, only on rate limits. The exception then becomes a `scorer_errors` entry in the SDK. Mustache HTML escaping is disabled globally (`chevron.renderer._html_escape = lambda x: x`, L72). That is a module-level monkey-patch.
- **Battle (pairwise)**: [battle.yaml](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/templates/battle.yaml) puts `{{output}}` as Response 1 and `{{expected}}` as Response 2 and asks "Is the first response better than the second?" → `{Yes:1, No:0}`. It uses a **fixed order, with no position swap or tie option**, so position bias is not mitigated. The UI also offers a human **Pairwise** card in diff mode **[doc]**.
- **ClosedQA**: `input` + `criteria` → `{Y:1, N:0}` ([closed_q_a.yaml](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/templates/closed_q_a.yaml)). Issue [#217](https://github.com/braintrustdata/autoevals/issues/217) says it dropped the reasoning-scoping clause from the OpenAI original.
- **Calibration**: none. `choice_scores` are hand-set constants. There is no logprob weighting, no judge-vs-human agreement tooling and no ensembles.
- **Non-LLM scorers**:
  - `Levenshtein`: `1 - dist/max_len` ([string.py L31-L63](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/py/autoevals/string.py#L31)).
  - `EmbeddingSimilarity`: cosine similarity rescaled by `max((s - expected_min)/(1 - expected_min), 0)` with `expected_min=0.7` by default ([L69, L197](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/py/autoevals/string.py#L197)). The floor is a hidden, model-dependent calibration constant.
  - `NumericDiff`, `ExactMatch`, `ListContains`, `ValidJSON`, `Moderation`.
  - RAGAS ports: `ContextEntityRecall`, `ContextRelevancy`, `ContextRecall`, `ContextPrecision`, `Faithfulness`, `AnswerRelevancy`, `AnswerSimilarity`, `AnswerCorrectness` (ragas.py).
- **JSONDiff** ([json.py L97-L190](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/py/autoevals/json.py#L97-L190)): recursive. Dicts give the mean over the **union of keys**. Lists are zipped pairwise and divided by the max length (order-sensitive, so no set matching). Strings go to a pluggable `string_scorer` (Levenshtein by default). Numbers go to `NumericDiff`. A None vs a value scores 0. Strings are auto-parsed as JSON unless `preserve_strings`. Pluggable leaf scorers are a nice design.

## Multi-turn / conversation & tool-use support
- **Thread variables in judge templates** (autoevals): if a template mentions `{{thread}}`, `thread_with_system`, `thread_count`, `first_message`, `last_message`, `user_messages`, `assistant_messages` or `human_ai_pairs` ([thread_utils.py L15-L27](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/py/autoevals/thread_utils.py#L15)), `LLMClassifier` calls `trace.get_thread()` and renders these variables ([llm.py L412-L472](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/py/autoevals/llm.py#L412-L472); `compute_thread_template_vars` [L249-L282](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/py/autoevals/thread_utils.py#L249)). The formatter unwraps content parts, pairs `tool_call` parts with their results, and middle-truncates long text. `human_ai_pairs` pairs the i-th user message with the i-th assistant message by index, which misaligns when turns are uneven. The thread itself comes from a **server-side preprocessor**, so the span→messages mapping is not in the open code **[inferred]**.
- **Tool-call assertions** (JS only; no Python equivalent found by grep): `agentAssertionScorer(cb)` ([agent-assertions.ts L219-L270](https://github.com/braintrustdata/braintrust-sdk-javascript/blob/2634cce523a742bbeff3a8c42ebc138ba4791fa5/js/src/agent-assertions.ts#L219)) gives the callback `assert.{equals, notEquals, contains, matches(schema), calledTool(name,{input,output,isError,times}), notCalledTool, toolOrder, usedNoTools, maxToolCalls}` (L47-L139). Trace-requiring assertions fetch `trace.getSpans({spanType:["tool"]})`. `toolOrder` is an ordered subsequence check (L370-L391). The score is **fraction of assertions passed**, with per-assertion results in metadata. Notably, when no trace exists, `usedNoTools` and `maxToolCalls` **pass** by design (comments at L396-L398, L413-L415). That silently passes if tracing is misconfigured.
- **Multi-turn datasets / simulation**: there is no conversation-typed `EvalCase`, turn-level scoring, user simulator or replay harness in either SDK (grep for "simulat"/"multi-turn" in framework code finds nothing). The docs recommend modeling a conversation as one trace with one span per turn (`span.export()` → `parent=`), or cross-trace correlation via `metadata.thread_id` plus a hand-written BTQL query inside a scorer **[doc: KB "Score multi-turn agent conversations across traces"]**.

## Online / production path
- The same span API with `init_logger(project=...)` ([L1900](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L1900)) writes to `project_logs`. The background HTTP logger batches uploads, with a bounded queue for logs that drops on overflow; for experiments the limit is disabled ([`enforce_queue_size_limit(False)` L1775](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L1775)).
- Online scoring rules (sampling rate, span filters, scorer choice) run server-side **[doc: score-online; KB "Configure root span filter for online scoring"]**. Scorers written for `Eval` that use `trace` work unchanged, because `LocalTrace` serializes to `{"trace_ref": {...}}` for remote invocation ([trace.py L490-L540](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/trace.py#L490-L540)).
- Retrospective scoring of existing experiments and logs is UI-driven; the added scores show up as new spans **[doc: interpret-results]**.
- OTel: `otel/` package and `flush_otel()` are called before scorers read spans ([framework.py L1713-L1726](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L1713)).

## Extension model
- Scorers are any callable. There is no registry: names come from `_name()`, then `__name__`, then a positional fallback (`_callable_name`, L1295). `Scorer` ABC for classes. Classifiers are a separate list.
- autoevals: add YAML + a subclass, or `LLMClassifier.from_spec(name, spec)` / `from_spec_file` (L475-L497). `init(client=, default_model=)` swaps the LLM client (oai.py L419).
- Reporters (`Reporter(name, report_eval, report_run)`, framework.py L1095) customize CLI output and exit codes.
- `parameters` (`EvalParameters` / `RemoteEvalParameters`) expose tunables to the hosted playground.
- Many auto-instrumentation integrations (`integrations/`, `wrappers/`).

## Strengths
- **One span schema for offline and online**, with scorers that can read the trace (`LocalTrace.get_spans`/`get_thread`, [trace.py L447-L644](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/trace.py#L447)). Trajectory scorers therefore run the same way in CI and on production logs.
- **Local span cache before remote fetch** ([trace.py L570-L585](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/trace.py#L570-L585)). Trace-reading scorers avoid a round-trip and a read-after-write race, and one shared flush serves concurrent scorers.
- **Scorer isolation per row**: one failing scorer does not sink the row or the run. Errors are captured as `metadata.scorer_errors` ([L1819-L1830](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L1819-L1830)). `error_score_handler` makes the "missing vs 0" policy explicit.
- **Row provenance**: every result carries `origin{dataset id, row id, _xact_id}` ([L1627-L1645](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L1627-L1645)), and experiments pin `dataset_version`. Results are reproducible against exact data.
- **Git-ancestor base selection** ([gitutil.py L109-L140](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/gitutil.py#L109-L140)): comparing against the merge-base on main is the right default for PR-style regression checks, better than "latest run".
- **Judge output via forced function-calling with an enum** ([llm.py L115-L133](https://github.com/braintrustdata/autoevals/blob/9546b28d08a4c4f55994e0626e4c327a9caa5ec0/py/autoevals/llm.py#L115-L133)) removes most parse failures. YAML specs make judges data, not code.
- **Classifications as a first-class, separate output** ([score.py L94](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/score.py#L94)) instead of encoding categories as floats.
- **Deterministic per-trial ids** with `upsert_id` (L1653-L1658) make re-runs idempotent.
- Workflow evals for async/webhook agents ([workflow_eval.py](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/workflow_eval.py)).

## Weaknesses
- **Comparison is opaque and statistically naive**: improvements and regressions are raw counts of rows that moved, computed server-side. There is no significance test, CI, noise threshold or trial aggregation **[doc/inferred]**. Local runs get none of it ([build_local_summary L1952](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L1952)). Issue [autoevals#219](https://github.com/braintrustdata/autoevals/issues/219) confirms trials are not consumed downstream.
- **Row identity = `input` by default [doc]**: any nondeterministic field in `input` silently breaks alignment and gives blank comparison rows (KB article).
- **Base selection has a silent failure mode**: git ancestry is only sent if org-level git collection is on (L1712-L1719, L1738). Otherwise the server falls back to "most recent experiment", which may be an unrelated branch's run. A base name that is not found only produces a warning (L1737).
- **Unbounded default concurrency**, and Python materializes every (row × trial) task up front (L1926-L1940). Large datasets can fire thousands of LLM calls at once and hold everything in memory.
- **Timeout is whole-run only** in Python ([L1445](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/framework.py#L1445)). A single hung task stalls everything until the global timeout, and then the whole run fails.
- **No task/scorer retries** in the SDK. autoevals retries only `RateLimitError`, up to 100 times (oai.py L636-L641), which can hang for a long time. There is no judge result cache.
- **Log upload drops batches** after 3 tries ([L1426](https://github.com/braintrustdata/braintrust-sdk-python/blob/e45a830a99cb225b7cb7704345363c1a95bfd5b8/py/src/braintrust/logger.py#L1426)). For experiments, this means results can silently go missing.
- **Signature-sniffing kwargs with a positional fallback** (L518-L523) can bind the wrong value to a mistyped scorer parameter.
- **Shared `nonlocal unhandled_scores`** across concurrent rows (L1599, L1819) is a race.
- **Scores must be in [0,1]** (score.py L47-L49). Latency, cost, counts and ordinal ratings must be forced into that range or put in metrics or metadata.
- **Multi-turn is a convention, not a model**: no conversation dataset type, turn-level scores or simulator. `get_thread` depends on a closed server-side preprocessor. `human_ai_pairs` pairs by index.
- **Tool assertions are JS-only** and treat "no trace" as "no tool calls" (agent-assertions.ts L396-L415).
- **Judge prompt quality**: Battle has fixed order and no tie option. ClosedQA dropped a scoping clause ([#217](https://github.com/braintrustdata/autoevals/issues/217)). Factuality's A/B weights (0.4/0.6) are arbitrary. EmbeddingSimilarity's `expected_min=0.7` floor is model-specific and undocumented as calibration.
- **Global side effects in autoevals**: the chevron HTML-escape monkey-patch (llm.py L72) and the process-global embedding cache (string.py L112).

## Worth adapting
- **Trace-aware scorer argument** (`trace.get_spans(type=…)`), backed by a local write-through cache with a single-flight flush. Trajectory and tool-use scoring then work identically offline and online.
- **Choice-label judges**: rubric as YAML (`prompt` + `choice_scores`), forced structured output with an enum, optional CoT field, rationale stored in score metadata. It is simple, inspectable and easy to diff.
- **Assertion-bundle scorer** for agents (`calledTool`/`toolOrder`/`maxToolCalls`/schema): per-assertion pass/fail in metadata plus an aggregate fraction. It is a good ergonomic layer over tool spans. Treat "trace missing" as an error, not a pass.
- **Base experiment = experiment at merge-base with the default branch**, with explicit override by id or name. This is the right default for regression comparisons.
- **Row provenance and dataset version pinning** on every result, with version as a monotonic transaction id and environment pointers as named aliases.
- **Separate numeric scores from categorical classifications.**
- **Per-scorer error capture** plus an explicit, pluggable policy for scoring missing values (skip vs 0).
- **Deterministic ids per (case, trial)** for idempotent re-runs. **Per-case `trial_count` override.**
- **Pluggable leaf scorers in structural diff** (JSONDiff with string and number scorers).

## Don't copy
- **Server-only comparison math.** Improvements and regressions computed in a closed backend, invisible and unreproducible locally, with no noise model. Comparison should be computable from stored rows with a stated statistic.
- **`input` as implicit row identity.** It couples identity to payload shape. Use an explicit, stable case id.
- **Hard [0,1] float as the only score type.** It forces lossy normalization and hides ordinal, boolean and unbounded metrics.
- **Unbounded concurrency default plus eager task creation.** Use a bounded default and a streaming work queue.
- **Global-only timeout; retry-only-on-429 with 100 attempts.** Prefer per-item and per-scorer timeouts and bounded, classified retries.
- **Signature-sniffing with a positional fallback** for scorer arguments. Pass one typed args object (as JS does).
- **Dropping telemetry batches silently** for eval results. Offline results must be durable or the run should fail loudly.
- **Fixed-order pairwise judge.** Pairwise needs position swapping and a tie option, or bias goes unmeasured.
- **Conversation semantics hidden in a server "preprocessor".** Thread extraction should be open, deterministic code.
- **Module-level monkey-patching** of a template engine and process-global unbounded caches in a scorer library.
